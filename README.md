# The kz Constitution

*A personal working constitution for AI-assisted mathematical research*

**公开版第一版（Public Edition 1） · 2026-10-26 · Zheng Kuang（匡正）**

“Constitution”在这里指作者为自身数学研究实践建立的工作性宪章，限定判断与修订的职责、程序和权限，而不制定适用于所有研究者的普遍规范。AI 受这些程序约束，但不构成其权威的来源。

这套文本记录作者与 AI 在数学研究、论文写作、选刊和论文压力测试中形成的工作制度。它保存规则、规则产生的理由，以及作者自己的写作与项目配置。公开版从 2026-10-22 的原工作版 R5.1 整理而来，保留其方法、语言和作者特点，并将私人工作记录排除在公开发行范围之外。

## 四项制度的分工

| 制度 | 负责的问题 |
| --- | --- |
| DCGI（闭依开生法） | 数学或事实判断是否有充分依据，其依赖与结论资格是什么。 |
| v5 | 有依据的判断是否应进入论文，以及如何作最小而完整的修改并核验结果。 |
| 选刊制度 | 哪个期刊及其评估路径能够评价论文实际完成的数学工作。 |
| 论文压力测试 | 哪些不利解读有文本和事实依据，论文已有何种回答，应作何种处置。 |

作者保留对研究方向、策略和个人风格的决定权；数学与事实主张仍须承担相应的论证责任。压力测试可以得到保留原文的结果，规则也保留适用边界、停止条件和重新开启问题的条件。

## 作者配置与项目配置

## 来源与生成文件

`sources/` 中的文件保存各组件的来源文本。两个完整理由档案分别是：

- [DCGI 理由档案](sources/DCGI/DCGI_v0.3.tex)
- [数学论文 v5 审查方法](sources/v5/Mathematical_Paper_v5_Audit_Method.tex)

理由档案说明规则的来路、作用和限度。实际执行以相应的执行文本为准；作者与项目规则以各自配置为准。原有的暂定条款和待闭合状态保留，本次公开整理不提升它们的资格。

合订 PDF 和 AI 执行文件由来源文件生成。维护时应先修改相关来源，再重新构建，避免手工修改生成文件而造成版本分叉。`SOURCE_MAP.json` 记录来源与合订内容的对应关系，`AI_SOURCE_BLOCKS.json` 记录十个执行来源块，`SHA256SUMS.txt` 用于核对发行文件。

## 本地构建

构建需要 Python 3、`pypdf`、`PyMuPDF`、Pandoc，以及包含 `ctex`、`xeCJK` 和 Fandol 字体的 XeLaTeX 环境。在仓库根目录运行：

```bash
python3 build/build_public_edition.py
```

构建生成两份合订文件，并更新来源映射、执行来源块记录和校验清单。源码及 AI 执行区块可逐字核对。PDF 排版受 XeLaTeX、字体与相关依赖版本影响，在不同环境中可能出现换行、字形或 PDF 字节差异；此时应使用新构建的校验清单核对本地文件，不能把原发行版的 PDF SHA-256 当作跨环境构建的预期值。中间文件写入 `.build/`，该目录不进入版本控制。具备兼容 `sha256sum` 命令的环境可在仓库根目录核对发行文件：

```bash
sha256sum -c SHA256SUMS.txt
```

本次发行属于公开文本与文件组织的整理；数学证明的核验状态仍以原有来源中的明确记录为准。
